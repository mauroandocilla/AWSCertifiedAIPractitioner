## Commands

```bash
npm install       # install dependencies
npm run dev        # start Vite dev server (serves at /AWSCertifiedAIPractitioner/, matching production base path)
npm run build       # tsc -b (typecheck) && vite build → output in dist/
npm run preview      # serve the production build locally
```

There is no test suite and no lint script configured — don't invent one.

## Architecture

This is a React 19 + TypeScript + Vite 6 single-page app: a study guide for the AWS Certified AI Practitioner (AIF-C01) exam. All content and UI copy is in Spanish; code/identifiers are in English.

### Routing

`HashRouter` (from `react-router-dom`), not `BrowserRouter` — deliberate, because the app is a static GitHub Pages deploy with no server-side rewrite rules, so hash-based routes work without a 404-redirect trick. `vite.config.ts` sets `base: '/AWSCertifiedAIPractitioner/'` to match the GitHub Pages project-site path.

Routes (`src/App.tsx`): `/` (Landing — a dashboard of cards linking into everything else), `/dominio/:n` (one of the 5 exam domains), `/servicios` (in/out-of-scope AWS services), `/glosario` (full glossary), `/como-estudiarlo` (study resources/links), `/formato-examen` (exam format, candidate profile, scoring strategy — not exam *content*, so it's kept separate from the domain pages). Every route except Landing renders a shared `QuickJumpBar` (`src/components/QuickJumpBar.tsx`) as a fixed top bar.

### Content is data-driven, not hand-authored JSX

`src/domainData.ts` and `src/glossaryData.ts` hold ALL of the exam content (domain/task/bullet structure and the full term-by-term glossary explanations) as plain data — components read from them, they don't contain prose. These two files were originally generated by `scripts/extract-content.mjs`, a one-off parser that pulled the content out of an earlier hand-written single-page HTML version of this guide. That script is not part of the build and does not need to run again — **when correcting or adding content, edit `domainData.ts`/`glossaryData.ts` directly**, not by re-running the extractor.

Content-accuracy convention: this content was audited bullet-by-bullet against the official AWS exam guide (docs.aws.amazon.com/aws-certification). Any term/service mentioned in the app that is NOT part of the official quoted objective text is marked inline as `<h4>Name <em>(extra, no está en el bullet oficial)</em></h4>` with a `<p><em>Fuente: ...</em></p>` line citing where it came from (e.g. the SkillCertPro cheat sheet in `docs/`). Keep following this pattern for any future non-official addition — never blend third-party or supplementary content into a bullet's "official" quoted text.

### Domain pages: master-detail layout

`src/components/DomainDetail.tsx` is the one component every `/dominio/:n` route uses (not five separate per-domain components) — it reads the domain's subsections/bullets from `domainData.ts`. Layout is a two-column master-detail: a left sidebar lists every bullet (grouped by subsection); clicking one shows that bullet's glossary explanation in the right panel via `GlossaryEntryContent`, driven by a `?b=<glossId>` query param on the same route (no navigation to `/glosario`). The sidebar is `position: sticky` (not `fixed`) specifically so it stays pinned while the panel scrolls but naturally scrolls away once its containing row reaches the footer — don't change this to `fixed` without re-solving the footer-overlap problem that motivated switching away from it.

`/glosario` reuses the same `GlossaryEntryContent` renderer for consistency (single source of truth for how a glossary entry renders), plus an index and a `?t=<glossId>` deep-link that scrolls to and highlights one entry — bullets elsewhere in the app link here via that query param.

### Theming

`src/index.css` defines light tokens on `:root` and dark overrides under both `@media (prefers-color-scheme: dark)` and `:root[data-theme="dark"]`. `src/components/ThemeToggle.tsx` is the single toggle (rendered once, fixed top-right, in `App.tsx`, so it's present on every route) that sets `data-theme` on `<html>` and persists the choice to `localStorage`. `index.html` has an inline pre-React script that reads `localStorage` and sets `data-theme` before mount, to avoid a flash of the wrong theme — keep that in sync if the storage key (`'theme'`) or values ever change.

### Deployment

GitHub Pages, deployed via `.github/workflows/deploy.yml` (Actions-based, triggers on push to `main`) — **not** the legacy branch-based Pages build. The repo's Pages source (`build_type: workflow`) is a setting on GitHub itself, not something in this repo, so a freshly created repo pointed at this code needs `gh api -X PUT repos/<owner>/<repo>/pages -f build_type=workflow` once, or the legacy build will try to serve `dist`-less raw source and fail.
